Kafka Design 


Kafka: Key, Partition, and Offset

Key: Determines which partition a message is sent to. Messages with the same key generally go to the same partition.

Partition: A topic is divided into partitions to enable parallel processing and scalability. Each partition is an ordered sequence of messages.

Offset: A unique sequential position assigned to each message within a partition. Consumers use offsets to track which messages they have read.

KEY TERMS
----------
1. Producer   : Sends messages to Kafka.
2. Consumer   : Reads messages from Kafka.
3. Cluster    : Group of Kafka brokers.
4. Broker     : Kafka server that stores data.
5. Topic      : Logical category for messages.
6. Partition  : Divides a topic for scalability.
7. Offset     : Position of a message in a partition.
8. Replication: Copies partitions across brokers
                for fault tolerance.



KEY       -> Determines the partition
PARTITION -> Stores messages in order
OFFSET    -> Message position within a partition

NOTE:
1. Same key generally goes to the same partition.
2. Ordering is guaranteed within a partition.
3. Each partition has its own offsets.
4. Different partitions can be consumed in parallel.

KEY TERMS
=========

1. Producer  : Sends messages to RabbitMQ.
2. Exchange  : Routes messages to queues.
3. Queue     : Stores messages until consumed.
4. Binding   : Connects an exchange to a queue.
5. Routing Key: Helps determine where messages go.
6. Consumer  : Receives and processes messages.
7. ACK       : Confirms successful message processing.
8. NACK      : Rejects a message; it may be requeued.








          KAFKA vs RABBITMQ
          =================

1. TYPE
   Kafka     : Distributed event streaming platform
   RabbitMQ  : Message broker

2. ARCHITECTURE
   Kafka     : Topics, partitions, offsets
   RabbitMQ  : Exchanges, queues, bindings

3. MESSAGE STORAGE
   Kafka     : Retains messages based on retention policy
   RabbitMQ  : Usually removes messages after ACK

4. MESSAGE CONSUMPTION
   Kafka     : Consumers pull messages
   RabbitMQ  : Broker pushes messages to consumers

5. MESSAGE REPLAY
   Kafka     : Supports replay using offsets
   RabbitMQ  : No native replay of acknowledged messages

6. MESSAGE ORDERING
   Kafka     : Ordering within a partition
   RabbitMQ  : Ordering within a queue, subject to configuration

7. SCALABILITY
   Kafka     : High-throughput distributed event streaming
   RabbitMQ  : Scales message delivery using queues and clusters

8. MESSAGE ROUTING
   Kafka     : Primarily topic and partition based
   RabbitMQ  : Flexible routing using exchanges and routing keys

9. ACKNOWLEDGMENT
   Kafka     : Consumers commit offsets
   RabbitMQ  : Consumers ACK individual messages

10. COMMON USE CASES
    Kafka     : Real-time analytics, logs, event streaming
    RabbitMQ  : Background jobs, notifications, task queues

KEY DIFFERENCE
==============
Kafka     -> Stores event streams for consumers to read
RabbitMQ  -> Routes and delivers messages to consumers
