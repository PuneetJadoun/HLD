A distributed system is a collection of independent computers or
services that communicate over a network and coordinate with each
other to provide a unified system to users.


1. Scalability
   → Add more servers when traffic increases.

2. Availability
   → If one server fails, others can continue serving users.

3. Fault tolerance
   → System can continue working despite failures.

4. Performance
   → Work can be distributed across multiple machines.

5. Geographic distribution
   → Servers can be placed in different regions closer to users.



STRONG CONSISTENCY

Write → Database
           ↓
       All reads
       immediately
       see latest value

Example:
Balance = ₹100

User updates → ₹50

Immediately:
Server 1 → ₹50
Server 2 → ₹50
Server 3 → ₹50




EVENTUAL CONSISTENCY

Write → Server 1
           ↓
      Replication
       ↙   ↓   ↘
   Server 2  Server 3

For a short period:
Server 1 → New value
Server 2 → Old value
Server 3 → Old value

After some time:
Server 1 → New value
Server 2 → New value
Server 3 → New value




Strong Consistency:
Every read after a successful write sees the latest value.

Eventual Consistency:
Reads may temporarily see stale data, but all replicas
eventually converge to the latest value.

Latency -- time delay in data transfer 
 
throughput -- amount of data transfer per unit time 

Bandwidth = maximum capacity of a network connection.


Fault: A fault is a defect or abnormal condition in a system that can cause incorrect behavior.

Failure: A failure occurs when a system or component fails to perform its required function as expected.

Resiliency is the ability of a system to continue providing its intended service, or recover quickly, when failures or unexpected problems occur.

Redundancy is having duplicate or backup components in a system so that if one component fails, another can take over and keep the system running.
